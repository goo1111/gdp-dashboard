| 항목 | 내용 |

| 사용 툴 | Figma · ChatGPT · Claude · Claude Code |

**프로젝트 목표**
감정 기록을 창작으로 확장해, 기록을 지속할 동기를 제공하는 것을 목표로 했습니다.

**어떻게 접근했나요?**
입력 · 축적 · 보상이 끊기는 문제를 구체화하고, 이를 **기록 → 축적 → 창작 → 소유**로 잇는 경험 구조를 설계했습니다.

**무엇을 확인했나요?**
프로토타입으로 감정 데이터에 따라 작품의 바탕 · 색 · 구도가 달라지는지, **기록 → 작품 생성 → 아카이브 저장**까지 흐름이 끊기지 않는지 점검했습니다.

**오른쪽 이미지(작품 카드 라벨)** 설렘 · 평온 · 슬픔 · 화남 · 기쁨 · 불안 · 복합 · 무기력 · 화남 · 캐릭터

## 02 Background

**제목** 감정 기록 수요는 크지만, **앱으로 꾸준히 이어가기는 어렵습니다**.
**부제** 감정 · 내면 기록은 **20~30대에서 상대적으로 높습니다.** 하지만 멘탈헬스 앱의 30일 유지율 중앙값은 **3.3%**입니다.

**01 수요** — 감정 기록 앱 하루콩의 1년
- 많은 기록 수요
- **2,700만 건** 1년 동안 쌓인 감정 기록
- 하루 평균 기록: 약 7.4만 건
- 감정 아이콘을 입력한 사용자: 200만 명 이상
- 출처: 머니투데이, 2024.01 · 블루시그넘 데이터 백서
- 결론: 감정을 기록하려는 수요는 큽니다

**02 이탈** — 멘탈헬스 앱 설치 후 30일
- 빠른 이탈
- **3.3%** 30일 뒤에도 앱을 여는 사용자 (중앙값)
- 설치 100명 중 30일 뒤 약 3명
- 출처: Baumel et al., JMIR 2019 · 앱 59개 분석
- 결론: 30일 뒤 남는 사용자는 100명 중 3명입니다

**03 대상** — 기록 방식 인식 조사 (2025.3 · 기록하는 880명)
- 감정 · 내면 기록 비율이 높은 20~30대
- **40%** 감정 · 내면을 기록한다 (일기, 감정 메모) · 18~29세
- 30대: 37%
- 전체: 32%
- 출처: 한국리서치 · 여론속의여론 제329-1호 · 표 c07
- 결론: 그래서 20~30대를 핵심 대상으로 정했습니다

**부제** 비교한 서비스는 기록을 쉽게 하고 흐름을 잘 보여 줍니다. **차이는 그 기록을 무엇으로 돌려주느냐에 있습니다.**

**02 포지셔닝**

**INSIGHT** 감정 데이터를 작품의 재료로 바꿔, **아카이브와 굿즈까지 잇는 구조**를 제안합니다.

## 04 Problem Definition

**제목** 감정 기록은 쉬워지고 보이게 됐지만, **다시 기록할 이유**로 이어지지 않습니다.
**부제** 선행 연구 3편에서 확인된 관찰을 **입력 · 축적 · 보상**으로 묶었습니다.

**선행 연구에서 확인된 3가지 관찰 (정성 분석)**

| | 관찰 | 내용 | 근거 |
| --- | --- | --- | --- |
| 01 입력 | 기록의 노력 | 기록에는 노력이 들어, 동기가 떨어지거나 잊으면 그만둡니다. | 18~25세 50명 정성 연구 (Beltzer, 2023) |
| 02 축적 | 이미 잘 보여 줌 | 기록을 쌓아 그래프 · 달력으로 보여 주는 기능은 이미 많고, 사용자도 유용하게 여깁니다. | 앱 32개 기능 분석 (Caldeira, 2017) · 인터뷰 22명 (Schueller, 2021) |
| 03 보상 | 확인 다음이 없음 | 기록을 해석하거나 다음 행동으로 잇는 지원은 부족합니다. | 행동 단계 지원 부족 (Caldeira, 2017) · 해석 · 개선 제안 부족 (Schueller, 2021) |

**설계 방향**

| | 방향 | 내용 |
| --- | --- | --- |
| 01 입력 | 부담 없이 남기기 | 단어 대신 위치로 고르고, 글은 한 문장이면 충분하게 |
| 02 축적 | 쌓인 기록을 재료로 | 기간별 흐름을 다음 결과물의 재료로 쓰게 |
| 03 보상 | 손에 남는 결과 | 확인으로 끝내지 않고 작품 · 굿즈로 돌려주게 |

**INSIGHT** 계속 기록하게 하려면 부담을 낮추는 것만으로는 부족합니다. 기록한 뒤 **돌아올 이유**가 필요합니다.

## 05 Concept Model

**제목** 사용자가 남긴 감정을, **감정로그가 작품으로 이어 줍니다**.
**부제** 사용자가 감정을 고르고 기간을 정하면, 감정로그가 흐름을 정리해 작품으로 돌려줍니다.

| | 01 감정 기록 (입력) | 02 흐름 축적 (축적) | 03 창작 · 소유 (보상) |

| 사용자 | 짧은 감정 기록 — 위치 고르기 + 한 문장 · 사진 · 음악 | 기간 선택 — 하루 · 주간 · 한 달 중 담을 기간 | 작품 저장 · 보관 — 갤러리 · 도감에 모으고 굿즈 미리보기 |

**서비스 가치 (원형, 가운데 정렬)**
쉽게 남기는 감정 기록
흐름으로 쌓이는 나의 감정
손에 남는 나만의 작품

## 07 HOME

**제목** 단어 대신 **감정 나침반**으로, 몇 번의 터치만에 **오늘의 감정**을 남깁니다.
**부제** **메인 감정과 세부 감정을 가장 빠르게 고를 수 있어** 감정 나침반을 택했습니다. 글은 한 문장이면 충분합니다.

**감정 나침반 설명**
- 세로축 — 에너지 높음 ↕ 낮음: 에너지가 높은지 낮은지 고릅니다.
- 가로축 — 불편함 ↔ 편안함: 감정이 내게 편한지, 불편한지 고릅니다.
- 결과 — 위치에 맞는 8가지 감정: 찍은 위치를 바탕으로 감정을 고르고, 세부 감정으로 좁혀 갑니다.

**단계**
1. 마음 위치 — 단어 대신 위치로 고릅니다
2. 세부 감정 — 섞인 감정은 최대 3개까지
3. 한 문장 — 글은 선택, 한 문장이면 충분
4. 홈 반영 — 홈 카드 · 이번 주 기록에 반영

## 08 CREATE

**제목** 기록을 고르면, 감정로그가 **한 장의 작품**으로 돌려줍니다.
**부제** 만들 방식과 기록만 고르면, **감정 데이터가 바탕 · 색 · 구도를 정해 한 장의 작품을 만듭니다.**

**작품이 정해지는 방식**
- 바탕 — 대표 감정 불안: 불안 이미지와 바탕색으로 그립니다.
- 색 — 나침반 가장자리 쪽 위치: 감정이 강한 쪽이라 색을 진하게 칠합니다.
- 구도 — 한 문장을 남김: 문장을 그림 아래에 깔아 구도를 쌓습니다.
- 스타일 — 직접 선택: 그림일기 · 컬러 라인 포스터 중 고릅니다.

**단계**
1. 창작 방식 — 그림 또는 캐릭터를 고릅니다
2. 기록 선택 — 하루 · 주간 · 한 달 기록
3. 재료 확인 — 사진 · 음악 · 동영상은 선택
4. 작품 완성 — 감정 데이터가 작품이 됩니다

## 09 CREATE Variations

**제목** 기록할 때마다 다른 작품이 돌아오도록 **결과의 경우의 수**를 설계했습니다.
**부제** 확인으로 끝나던 결과를, **내 감정과 내가 고른 방식에 따라 달라지는 작품으로 바꿨습니다.**

- 결과 화면 — 스타일 탭으로 바로 바꿔 봅니다
- **내가 고르는 것 · 방식 · 스타일** (불안 · 하루 기록): 작품 · 그림일기 / 캐릭터 · 그림일기 / 작품 · 컬러 라인 / 캐릭터 · 미니멀
- **내가 고르는 것 · 기간** (불안 · 작품 · 그림일기): 하루 / 주간 / 한 달
- **기록이 정하는 것 · 8가지 감정** (작품 · 그림일기 · 하루 기록): 화남 · 기쁨 · 무기력 · 복합 · 불안 · 설렘 · 슬픔 · 평온

**요약**
- 12가지 조합 — 방식 2 × 스타일 2 × 기간 3
- 8가지 감정 — 감정마다 다른 이미지와 바탕색
- 미리 만든 이미지 80개로 구현 · 캐릭터 한 달은 주간 이미지 사용

## 10 ARCHIVE

**제목** 한 달의 **감정 흐름**을 돌아보고, 마음에 든 작품은 굿즈로 이어 갑니다.
**부제** 만든 작품은 날짜별로 나의 창작물에 모이고, **마음에 든 작품은 5가지 굿즈에 대어 봅니다.**

**굿즈 미리보기**
- 종류 — 5가지 굿즈: 엽서 · 스티커 · 키링 · 폰케이스 · 에코백
- 가이드 — 인쇄 영역 표시: 재단선 · 안전 영역을 켜고 끕니다.
- 배치 — 맞춤 · 채움: 확대와 위아래 위치를 조절합니다.

**단계**
1. 감정 달력 · 감정 리포트 — 한 달의 감정 색과 흐름
2. 감정 달력 · 나의 창작물 — 날짜별로 만든 작품이 모입니다
3. 작품 상세 — 공유하거나 굿즈로 이어 갑니다
4. 굿즈 미리보기 — 작품을 굿즈에 대어 봅니다

## 11 Design System

**제목** 색 하나에 감정 하나, **토큰과 컴포넌트**로 화면 전체를 묶었습니다.
**부제** Primitive 54 → Semantic 59 → Component 4. Figma 변수 147개와 CSS 변수 이름을 1:1로 맞추고, Figma 컴포넌트에는 hex를 직접 쓰지 않았습니다.

**Typography** — Pretendard
- Title · 24 / 700 — "짜증난 마음"
- Body · 16 / 400 — "회의가 길어져서 짜증이 났다."
- Caption · 12 / 600 — "10월 5일 월요일"

**Spacing · Radius**
- Spacing: 2 · 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 — 4 · 8 기준 10단계 · padding · margin · gap 1,970곳을 토큰으로
- Radius: 8 태그 · 12 칩 · 16 카드 · 20 버튼 · full 토글

**Color**
- 감정 8색 — 그날의 감정
- 감정 tint — 기록한 날
- 차콜 — 누르는 것
- 웜 그레이 — 보조 정보
- 아이보리 — 바탕
- 색마다 맡는 역할은 하나 — 글보다 색으로 먼저 그날의 감정을 읽습니다.

**Emotion** — 감정 8색 · fill: 설렘 · 평온 · 기쁨 · 복합 · 슬픔 · 불안 · 무기력 · 화남

**Neutral** — 글자 대비 (캔버스 위): 950 13.8:1 · 900 16.5:1 · 600 6.5:1 · 500 5.1:1 · 400 장식 · 200 테두리

**Components**
- 버튼: 저장하기 · 이전 · 기록하기 · 다음 — 기본 · 보조 · 비활성 × L 48 / M 40 — 상태는 토큰으로만 바뀝니다.
- Input (빈 칸 / 입력 중): "오늘을 한 문장으로 0 / 100" · "회의가 길어져서… 16 / 100"
- Chip · Toggle: 짜증난 · 화난
- Day Cell (기록한 날 · 선택 · 빈 날): 2 · 3 · 4 · 5 · 6 · 7

**INSIGHT** 감정색은 기록, 차콜은 누르는 것 — **색의 의미를 고정해 글보다 먼저 그날의 감정이 읽히게 했습니다.**

**제목** 다음 단계는, 작품이 돌아올 때 사용자가 **다시 기록하는지** 확인하는 것입니다.
**부제** 아직 사용자 테스트 전입니다. **3명 사용성 테스트로 흐름을 다듬고**, 출시 후에는 지표로 "계속 기록하는가"를 검증합니다.

**검증 단계**
1. 다음 버전 전 — **사용성 테스트**: 참가자 3명 · 1인 30분 · Think-aloud / 과업 4개: 기록하기 · 홈 이해 · 돌아보기 · 작품 만들기
2. 테스트 직후 — **반복 문제 개선**: 2명 이상 반복된 문제부터 수정 / 행동 → 발언 → 원인 → UI 개선 → 다시 확인
3. 공개 이후 — **출시 후 측정**: 작품을 만든 사용자와 만들지 않은 사용자의 30일 재기록률 비교 / 참고: 멘탈헬스 앱 30일 중앙값 3.3%

**성공 지표**

| 구분 | 목표 | 기준 | 질문 |
| --- | --- | --- | --- |
| 기록 | 2 / 3명 | 기록 3단계를 도움 없이 완료 | 감정 기록을 부담 없이 끝내는가 |
| 이해 | 2 / 3명 | 기록 → 작품 연결을 설명함 | 내 기록이 작품의 재료가 됨을 이해하는가 |
| 가치 | 2 / 3명 | 작품을 '내 감정의 결과물'로 표현 | 단순한 이미지가 아니라 내 것으로 느끼는가 |
| 지속 의향 | 2 / 3명 | 앞으로도 기록하고 작품을 만들 의향을 보임 | 열린 질문: "다시 기록한다면 어떤 이유일까요?" |

**INSIGHT** 이 프로젝트의 질문은 하나입니다 — **기록이 작품으로 돌아오면, 사람들은 다시 기록하는가.**

## 13 Retrospective

**제목** 화면을 덧칠하기보다 **원본을 고치는 것**이 가장 빠른 길이었습니다.
**부제** 디자인 시스템으로 품질을 원본에서 지킨 것은 남기고, 사용자 검증과 용어 정리를 늦게 시작한 것은 다음 프로젝트에서 바꾸겠습니다.

**KEEP 잘된 점**
- **202 → 0** 원본을 고치니 접근성도 따라왔다 — 보정 스크립트 대신 토큰 값을 고쳤습니다.
- **5곳 → 1곳** 감정 색을 데이터로 다뤘다 — 같은 감정은 어느 화면에서나 같은 색입니다.
- **145 / 145** Figma와 코드가 같은 이름을 쓴다 — 컴포넌트 색이 모두 변수로 연결됩니다.

**PROBLEM 아쉬운 점**
- **2차 자료** 사용자를 직접 만나지 못했다 — 리서치는 논문 · 리뷰뿐, 테스트는 아직입니다.
- **2,900여 개** 버전마다 덧댄 스타일이 쌓였다 — 작은 수정에도 스타일 규칙끼리 충돌했습니다.
- **사진 · 영상** 첨부 규칙을 제대로 구현하지 못했다 — 첨부는 받지만, 작품에 반영하지 못합니다.

**TRY 다음에 다르게**
- **먼저** 토큰과 컴포넌트를 화면보다 먼저 — 시스템을 먼저 세우고 화면을 올리겠습니다.
- **초기에** 용어 사전을 첫 주에 확정 — 문구 · 문서 · 코드가 같은 단어를 씁니다.
- **처음부터** 직접 인터뷰와 테스트를 일정에 고정 — 사용자 검증을 화면 설계보다 앞에 두겠습니다.

**INSIGHT** 다음 프로젝트의 순서 — **사용자를 먼저 만나고, 이름과 시스템을 정한 뒤, 화면을 만든다.**
